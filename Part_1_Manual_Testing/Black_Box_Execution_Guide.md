# Black-Box Test Execution Guide

Use the `Equivalence Partitioning`, `Boundary Value Analysis` and `Decision Table` sheets in `Black_Box_Testing.xlsx`. All status cells remain `Not Run` until observed. Capture evidence without passwords, tokens or personal data.

## Equivalence partitions

| Input | Representative inputs | Manual action | Expected behavior from source |
|---|---|---|---|
| Email | unique browser-valid address; malformed string; existing address with changed letter case; blank | Use `/register`; attempt each input with other required values valid. For malformed email, observe browser validation. For case variation, submit the existing account address with a different letter case. | Browser `type=email` blocks malformed input during normal form submission; required field blocks blank. Backend lowercases lookup and storage, so duplicate case variants should be rejected. A unique address proceeds if remaining fields are valid. There is no separate server email-format validator. |
| Password | 5, 6 and 7 characters | Register with matching password/confirmation for each length and a fresh synthetic address. | 5 is rejected; 6 and 7 pass the length rule. The account creation still depends on other valid fields and unique email. |
| File type | valid JPEG, valid PNG, valid PDF, `.txt` | Sign in and use `/upload`. Try each file. For server validation of `.txt`, use an API client with multipart `document` and bearer auth because the browser chooser may filter it. | `image/jpeg`, `image/png`, `application/pdf` are accepted by Multer. Other MIME types are rejected with HTTP 400. File extensions alone do not prove MIME behavior. |
| File size | 10,485,759 / 10,485,760 / 10,485,761 bytes | Use exact-size fixtures generated by `python create_boundary_files.py`; verify file sizes in the printed output or file properties, then upload through the UI. The >limit UI case is rejected before reaching server. Test the backend rule separately with an API client if needed. | UI and Multer limits are `10 * 1024 * 1024` bytes. Below and exact limit pass size validation; one byte above is rejected. For files within the size limit, other conditions (MIME and authentication) still apply. |

## Decision table rules R1–R8

The route order is authentication (`protect`) before Multer file parsing, then upload controller. Use a disposable account and test files. “API client” means a request to the local API, not production.

| Rule | Conditions | How to execute | Expected result |
|---|---|---|---|
| R1 | Authenticated + allowed MIME + <=10 MiB | Sign in; upload a valid small PNG in `/upload`. | Upload accepted; success shown and a document record appears. |
| R2 | Authenticated + disallowed MIME + <=10 MiB | Sign in; send a small `.txt` as multipart field `document` to `POST /api/documents/upload` using a test API client and bearer token. | HTTP 400 unsupported file type; no document record. |
| R3 | Authenticated + allowed MIME + >10 MiB | Sign in; first observe UI rejection with oversized PNG fixture. Then, if validating server defense, send it through an API client with test bearer token. | UI rejects before request; direct API request is rejected by Multer with the size-limit message. Do not describe the UI check as backend execution. |
| R4 | Authenticated + disallowed MIME + >10 MiB | Send an oversized `.txt` as multipart `document` with bearer token using a local API client. | Request is rejected. Record whether unsupported type or size error is returned first; source does not promise precedence for simultaneous invalid conditions. |
| R5 | Unauthenticated + allowed MIME + <=10 MiB | Clear local session; send a small valid PNG to upload endpoint without Authorization header. | Rejected as unauthorized before file acceptance; no document record. |
| R6 | Unauthenticated + disallowed MIME + <=10 MiB | Send a small `.txt` without Authorization header. | Authentication middleware rejects before Multer evaluates the type. |
| R7 | Unauthenticated + allowed MIME + >10 MiB | Send an oversized valid PNG without Authorization header. | Authentication middleware rejects before Multer evaluates the size. |
| R8 | Authenticated + allowed MIME + exactly 10 MiB | Sign in; upload `upload_10485760.png` from the generated fixture folder. | Client `>` check and Multer's configured limit should accept exact max size; document is recorded. Inspect both UI and list/detail result. |

For each API rule, record HTTP status, safe response message, whether a record was created, and screenshot or API-client evidence. Never include the bearer token in the evidence. Do not delete records unless the test case says to use a disposable item.
